# Initial Lovable prompt

Use the following as the first message when the user starts the application build. Attach the phase-A documents; do not assume the local filesystem is visible to Lovable.

---

Build **ASHA Saath / आशा साथ**, a hackathon prototype for Healthcare 03: an ASHA/ANM visit scheduling optimizer extended with locally accountable NGO document-help referrals.

Start with the government-style application shell and a working synthetic visit planner. Keep your generated framework/config/lockfile; inspect the actual stack first. Current new Lovable projects use TanStack Start, React and TypeScript.

Read the attached product context, PRD, TRD, design system, UI/UX and fixture configuration. Preserve these decisions:

- 24 synthetic tasks, two assigned workers, fictional catchment, one document-navigation category and three fictional offers.
- Original PS is central: CSV validation and stable task identity, supplied approved/synthetic priority, explicit locality grouping/nearest-neighbour, feasible daily route, travel assumptions, every unserved reason and future coverage projection.
- No AI clinical classification, real records, government identifiers or live partner claims.

Visual style must resemble a clear Indian government service portal: original ASHA Saath wordmark, navy utility bar, white identity header, navy navigation, small saffron active underline, white structured panels, formal tables/forms, Hindi/English control and ownership/help footer. Use #102A43 navy, #1D4E89 primary, #F29D38 saffron, #172B4D text and #F5F7FA page background. Saffron uses navy text. Body/buttons 16px+, mobile actions 48px, radius 6px. No copied national/state emblem or promotional hero in operational screens.

Every page visibly labels the product **“Synthetic demonstration — no live government or NGO connection.”**

Create three clearly labelled preview roles: worker mobile, coordinator desktop and provider intake. The preview selector is not authentication. Worker Today/Needs/Help navigation; coordinator Overview/Caseload/Plans/Needs/Service network/Reports; provider Requests/Accepted work/Capacity.

For this first phase, implement the shell, demo loader and planner/visit screens with typed synthetic data and a deterministic domain module. Include explicit loading, invalid CSV, unserved/empty, Hindi and mobile states. Keep support screens as clearly labelled skeletons until the next phase; do not fake accepted/delivered/closed backend results.

Show the actual framework and files used, completed behaviours, checks run and what remains. Do not provision a second backend, install unrelated integrations, contact NGOs, use real records or publish as part of this first phase.

---
