# Government-style UI/UX revision — 9 October 2026

The user asked to finish the local interface and usability before deployment. This revision continues the imported TanStack Start application. It does not regenerate the Lovable project or change the scheduling policy.

## Implemented changes

- Compact utility bar with fictional-demo label, Hindi/English and text size; original bilingual masthead; one navy navigation row. Account switching and demo controls are inside the account menu. No copied government emblem or claimed government affiliation.
- Coordinator overview: four explained metrics, separate urgent health queue, three clear starting actions, ASHA plan register, request follow-up and NGO availability. “Could not fit” explicitly counts exclusions from saved plans, not every unplanned district visit.
- Visit register first, with search, worker/area filters, readable priorities/dates and mobile cards. “Add visit list” opens Upload → Check → Save. Identity/reference fields are expandable. Re-import preview preserves saved outcomes and shows unchanged records.
- Planner starts with ASHA and date. Advanced shift/travel inputs are expandable. Preview and save are distinct; route order, assumptions, future tasks and due tasks excluded from the plan remain explainable.
- ASHA screen starts with the next visit and a large recording action. The visible “View route map” control is directly underneath. Outcome form receives focus when opened. Four plain outcome choices precede optional document-help capture.
- Help requests show five steps and who must act next. Named-recipient permission and exact shared fields remain explicit. Before permission, withdrawal is labelled “Cancel this help request”; after permission it says “Stop sharing this request”. Failed withdrawal remains an error in the confirmation dialog.
- NGO acceptance moves to accepted work. Arrangement uses a supported method plus date/from/until inputs. Delivery reporting, recipient confirmation and coordinator closure remain separate actions.
- NGO directory describes service catchments and actual available capacity. Coordinator cannot edit a provider's capacity. Reports use readable summaries, separate future estimates and expandable audit details. Help/privacy copy reflects maps and the new navigation.

## Interactive maps

`/coordinator/map` provides Visit routes and NGO service areas. The route also appears in plan preview and the worker screen. Leaflet 1.9.4 is loaded only inside an effect after the browser mounts; SSR does not instantiate a map.

Markers use existing, explicitly synthetic coordinates. A saved plan's stop order drives numbering. Dashed lines are illustrative order, not road routing or GPS directions. Coverage markers are means of unique fictional sample points within a locality; they are not NGO offices or administrative polygons. Coverage uses the offer's actual catchments, separately from office address.

The map supports zoom, pan, Show all, stop selection and popups. The ordered text list remains available without tiles. The tile-failure message/retry path is implemented but an externally induced tile outage was not browser-tested. OpenStreetMap attribution is visible; no offline prefetch is implemented. Tile use and request metadata are explained on the privacy page.
